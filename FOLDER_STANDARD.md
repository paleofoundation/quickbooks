# Folder standard — drop these here every period

The single biggest speed win. One folder per year (and a `monthly/` subfolder for interim drift
checks). The scripts auto-discover files by these conventions; discovery is tolerant of
space/underscore differences, so exact filenames are not critical — the patterns below are what
`close.py` looks for.

```
<Period folder>/                              # passed as --period
  Credit Cards <YEAR>/
    <Account Name>/                           # one folder per bank/card, e.g. "Capital One 5391:7933"
        <real transaction download>.csv       # the REAL account export (date, description, debit, credit)
        Statement_MMYYYY_*.pdf                # every monthly statement PDF (kept for the human; see note)
  QBO exports/
      <card> Register (NN).xls                # QBO register export for EACH credit-card account
      <Entity>_Profit and Loss.csv            # QBO P&L, full year, accrual
      <Entity>_Balance Sheet*.csv             # QBO Balance Sheet
      Audit Log*.csv                          # QBO Audit Log export (REQUIRED for the controls layer)
  statement_balances.csv                      # real month-end balances per account (see below)
  Owner accounts/
      BOC <Owner> <YEAR>/TransactionHistory*.csv   # each owner's Bank of Cyprus export (EUR)
      Capital One personal*/*.csv                  # owner personal-card exports
  Receipts/
      *.pdf                                   # vendor receipts/invoices (Amazon, iHerb, etc.)
  close_<entity>_<YEAR>/                       # GENERATED by close.py — do not hand-edit
```

## `statement_balances.csv` (NEW in v2) — the balance truth

Statement **PDFs do not parse reliably** for the month-end balance, so the real balances are recorded
in a small CSV you fill from the statements by hand (one number per account per month). This is the
ground truth the balance phantom and the monthly drift check compare against. Suggested shape:

```csv
account_label,month_end,statement_balance
Capital One Venture X,2025-12-27,12873.77
Visa 1044,2025-12-31,1945.60
```

The year-end figure also lives in `config/entities.yaml` as each account's `statement_balance_eoy`
(plus `carry_in_prior_year` for the prior-year overstatement carried in). Keep the two in sync.

## How to export — QuickBooks Online (one company at a time)

The QBO connector and report widgets do **NOT** return numbers to the model; the CSV/register exports
below are **mandatory**. The connector works on **one company at a time** — switch companies between
St. Gertrude and Paleo.

- **Registers:** Accounting → Chart of Accounts → the credit-card account → Run report / View register
  → Export. One per credit-card account.
- **P&L / Balance Sheet:** Reports → Profit and Loss / Balance Sheet → set the period (full year,
  accrual) → Export to CSV.
- **Audit Log:** Settings (gear) → Audit Log → filter to the period → Export. This is what the
  `audit_log` control reads to corroborate "who entered this" past the shared-login history.

## How to export — banks / cards

Download the dated CSV transaction file for each account. Save statement PDFs for the human's records,
but transcribe the month-end balance into `statement_balances.csv` (PDFs don't parse).

- **Capital One** (`csv_schema: capital_one`) — Transaction Date / Debit / Credit (USD). Download the
  dated transaction CSV per card; e.g. `*7933*transaction_download*.csv`.
- **Chase** (`csv_schema: chase`) — signed Amount column; download the activity CSV.
- **Wells Fargo** (`csv_schema: wells_fargo`) — **headerless** CSV: Date, Amount(signed), *, *,
  Description. Download as-is; the loader handles the missing header.
- **American Express** (`csv_schema: amx`) — signed Amount; export the `activity.xlsx`/CSV.
- **PayPal** (`csv_schema: paypal`) — signed Amount/Gross/Net.
- **Bank of Cyprus** (`csv_schema: numbers` / `load_boc`) — EUR, EU number format (`.` thousands, `,`
  decimal), preamble rows before the `Date,` header. Export the period transaction history CSV per
  owner. (Apple `.numbers` working files are read directly via the `numbers` schema.)

Set each account's `csv_schema` in `config/entities.yaml` to match its bank so the loader parses
debits/credits correctly.

Tip: keep the prior year's folder intact — the year-over-year roll-forward (opening balances and
`carry_in_prior_year`) needs it.
